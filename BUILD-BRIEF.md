# PoultryOS — Build Brief for the Coding Agent

**Goal:** build the PoultryOS web application — a responsive, offline-tolerant, multi-tenant SaaS for Indian poultry farms (layer, broiler, hatchery) — on Supabase. The same web build will later be wrapped as a mobile app (Capacitor), so build it mobile-first and keep it a single codebase.

**You are not starting from scratch.** The following already exist in the `poultryos/` repo and are the source of truth; read them before writing code:

| Asset | Path | Use it for |
|---|---|---|
| Database schema + RLS + KPI views | `supabase/migrations/0001_schema.sql`, `0002_subscriptions.sql` | Every table, enum, policy and view the app reads/writes. Do not redesign; extend with new migrations only. |
| Demo seed (2 tenants, full data) | `supabase/seed.sql`, regenerated by `scripts/gen_seed.py` | Local dev data. VKR Poultry Farms (layer + broiler), KS Farms (broiler + hatchery). |
| Edge functions | `supabase/functions/{sync-apply,ai-triage,market-rates,daily-alerts,razorpay-webhook,provision-tenant}` | Backend logic the web app calls. Deploy as-is; fix bugs if found. |
| **UI reference (the design)** | `demo/index.html` (self-contained; open in a browser) | Every screen, flow, label, empty state, colour, type scale and interaction. **Replicate it faithfully in React.** |
| Demo data as JSON / XML | `demo/data.json`, `demo/poultryos_demo_data.xml` | Shape of the derived view-models the screens expect. |
| Design tokens / strings (en + te) | `android-xml/res/values/*.xml`, `values-te/strings.xml` | Palette, Telugu strings. |
| Architecture doc | Claude doc "PoultryOS — Technical Architecture" (export in repo as `docs/architecture.md` if present) | Rationale, roles, roadmap. |
| Flutter scaffold | `mobile/` | **Ignore.** Superseded by the web-first decision; keep for reference only. |

## 1. Stack (fixed — do not substitute)

- **Framework:** Next.js 14+ (App Router) + React 18 + TypeScript strict.
- **Styling:** Tailwind CSS with the PoultryOS tokens (section 5); shadcn/ui for primitives (Sheet, Dialog, Tabs, Select, Toast, Command). No other component kits.
- **Data:** `@supabase/supabase-js` v2 + `@supabase/ssr` for auth cookies. TanStack Query v5 for server state. Zod for all form schemas.
- **Charts:** Recharts (line, bar, sparkline). One y-axis per chart, never dual-axis.
- **Forms:** react-hook-form + Zod; one generic `<SchemaForm>` driven by a field schema (section 7).
- **Offline:** PWA (next-pwa or Serwist) with an **outbox** in IndexedDB (Dexie). Daily log, mortality, attendance, photos must save offline and replay through the `sync-apply` edge function.
- **i18n:** next-intl. Locales: `en`, `te`, `hi` at launch (`ta`, `kn`, `mr` stubs). All user-facing strings go through messages files; seed from `android-xml/res/values*/strings.xml`.
- **Mobile wrapper (later phase):** Capacitor 6 (`@capacitor/core`, `camera`, `geolocation`, `push-notifications`, `filesystem`). Build with `output: 'export'`-compatible routes **or** point Capacitor at the hosted URL. Keep all platform calls behind `lib/platform/*` adapters (`takePhoto`, `getPosition`, `registerPush`) with web fallbacks (`<input capture>`, `navigator.geolocation`, Web Push), so nothing in the UI imports Capacitor directly.
- **Hosting:** Vercel (web) + Supabase project in `ap-south-1` (Mumbai). CI: GitHub Actions (`.github/workflows/db.yml` already deploys migrations + functions on push to `main`).

Package manager: pnpm. Node 20. ESLint + Prettier. Vitest for unit tests; Playwright for e2e (phone viewport 390×844 and desktop 1280×800).

## 3. Auth, tenancy, roles

- Supabase Auth, **phone OTP** primary (SMS provider: MSG91 via custom hook or Twilio). Email magic link as fallback for office users.
- JWT `app_metadata` carries `{ tenant_id, roles: [...], platform: boolean }`. RLS in the DB enforces tenant isolation; the client never filters by tenant manually.
- Roles (from schema enum `app_role`): `platform_admin, platform_support, tenant_owner, finance, farm_manager, shed_supervisor, veterinarian, store_keeper, vendor, customer, contract_farmer, auditor`.
- `useRole()` gates UI only (hide/disable); the DB is the real guard. Matrix:
  - Supervisor: Home (limited), Log, Farm (own sheds), Attendance (mark), Equipment (report issue). No Money.
  - Farm manager: everything in tenant except billing/plan.
  - Finance: Money, Vendors, Customers, Reports.
  - Vet: Health, batch screens, confirm AI cases.
  - Owner: everything. Platform staff: `/admin`.
- Tenant switcher: platform staff can impersonate (audited: insert `audit_log` row); normal users see only their tenant. Persist last tenant in `localStorage` with a validity check (fall back to first tenant if missing).

## 4. Navigation and responsive rules

- **Mobile (< 768 px):** 5 bottom tabs — Home, Farm, Log, Money, More — with Telugu sub-labels when locale is `te`. Content scrolls under a sticky top bar. All create/edit actions open a **bottom sheet** (shadcn `Sheet side="bottom"`, max-height 88 vh, scrollable).
- **Tablet / desktop (≥ 768 px):** same five destinations as a left rail; More's ten sections become rail items. Bottom sheets become right-side drawers (`side="right"`, 480 px). Content max-width 1120 px, two-column where the demo stacks (e.g. batch page: charts left, lists right).
- Side gutter 16 px minimum at every width; no horizontal page scroll; tables and the monthly register scroll inside their own container.
- Tap targets ≥ 44 px. Numeric inputs use `inputmode="decimal"`. Font-size on inputs ≥ 16 px (prevents iOS zoom).
- Dark mode: honour `prefers-color-scheme`; tokens in section 5 define both.
- Every list has an explicit `+ Add` action in its header; every record row has its primary action inline (Pay, Receive, Mark done, Report issue, Close, Reorder).

## 7. The generic form (`<SchemaForm>`)

Every create/edit in the app is a schema, not a bespoke screen. Replicate the demo's `form()` helper:

```ts
type Field = { id: string; label: string; type?: 'text'|'number'|'date'|'tel'|'select'|'textarea'|'photo';
  options?: [value: string, label: string][]; value?: unknown; half?: boolean; required?: boolean;
  hint?: string; step?: string; placeholder?: string };
type FormSpec<T> = { title: string; intro?: string; fields: Field[]; schema: ZodSchema<T>;
  submitLabel: string; danger?: boolean; onSubmit: (values: T) => Promise<void>; extra?: ReactNode };
```

Rendered as a two-column grid (`half` fields share a row; others span), photo fields use `lib/platform/photo` and stage into the outbox with GPS + timestamp + SHA-256, submit button full-width accent, cancel below. Mobile: bottom sheet. Desktop: right drawer. On success: toast with the business consequence (e.g. "GRN posted · stock +200 · bill ₹2.96 L booked · 3-way match OK") and navigate as the demo does.

Forms to implement (names match demo `ACT` keys): addFarm, addShed, addBatch, mort, vaccDone, addVacc, addVisit, batchState, closeBatch, saleOpen, addBill, payQuick/payOpen, addCustomer, addRate, addWorker, addAdvance, addVendor, raisePO, grnOpen, addItem, addAsset, reportIssue, closeTicket, serviceDone, inviteUser, addDoc, tenantOpen, tenantManage. Each has a Zod schema in `lib/schemas/` and a mutation in `lib/queries/`.

**Side effects are part of the spec** (do them server-side in a Postgres function or the mutation, in one transaction): placing a batch generates the vaccination schedule from `vaccine_master` and books the DOC bill; a vet visit with a fee books a bill; closing a batch with a buyer raises an invoice and sets `closed_on`; GRN posts `stock_movement` + bill; closing a ticket with cost books an equipment bill; a payment updates `paid`/`status` on its bill/invoice; a sale on credit sets `due_date = date + customer.credit_days`; eggs and live birds are GST-exempt, manure 5%.

## 8. Offline and sync (must work before launch)

1. Dexie DB mirrors: `batches`, `daily_logs`, `market_rates`, `workers`, `attendance`, `items/stock`, `assets`, plus `outbox` and `pending_media`.
2. Every write in Log, Mortality, Attendance, Vaccination-done, Report-issue goes **local first**, then an outbox row `{op_id uuid, table, action, payload, base_version}`.
3. `lib/offline/sync.ts` replays the outbox to the `sync-apply` edge function when online (and every 15 min via Background Sync where supported); applies `applied | duplicate | conflict | error`; conflicts surface in a "Needs review" list for managers.
4. Photos upload separately to the private `evidence` bucket with pre-signed resumable uploads; the record syncs first with `media_pending`.
5. Pull deltas per table by cursor (`created_at`/`sync_version`), as in `mobile/lib/data/sync/sync_service.dart` (port the logic).
6. UI shows pending-count badge on the Log tab and an offline banner; never block entry on connectivity.

## 11. Non-negotiables

- Mobile-first; every screen usable one-handed on a ₹10k Android phone over 3G.
- No data outside RLS: the client uses the anon key + user JWT only; service-role keys exist only in edge functions.
- Every money or stock mutation is transactional and idempotent (client `op_id`).
- Evidence photos: in-app capture only, GPS + timestamp + hash stored, never gallery picks for evidence fields.
- AI results are advisory: always show confidence, "beta" tag, and a vet-confirm action; store `model_version`.
- Keep `scripts/gen_seed.py` the single source for demo data; if you change the schema, update the generator and regenerate `seed.sql` + `demo/data.json`.
- Do not invent new tables when one exists; add migrations `0003+` only for genuinely missing entities (`tenant_document`, `report_job`, `worker_advance`).
